# 项目工作流 · M590Bridge

## 目标

让任意 Agent（Claude Code / Codex / 其它）在新会话中只靠仓库文件即可接手：规则、计划、任务、验证与风险都落在 `docs/`。

## 中文口令

| 用户说 | 动作 |
|--------|------|
| 新项目 | 建最小规则与 task；不写业务代码（除非同时要求开发） |
| 接手 / 摸底 | 只读扫描；更新 discovery；可建 task；不改业务代码 |
| 继续项目 | 读规则/计划/task/git；报告状态与唯一下一步；默认不开发 |
| 开始开发 | 只做当前一个 pending/in_progress task |
| 验收一下 | 对照 task 验收；跑验证；不新增功能 |
| 让执行代理修 / 返工 | 只修验收问题 |
| 补文档 | 对照源码与 docs 补齐；默认不改业务代码 |

## 固定流程

1. **恢复上下文**：`AGENTS.md` → 专用补充 → `workflow` / `documentation-rules` / `environment-policy` → `plans/current.md` → 当前 task → git 状态  
2. **只选一个 task**：用户指定 > 计划指向 > 最新 pending  
3. **守边界**：只改 task 允许范围  
4. **真实验证**：运行 task 中的验证命令并记录  
5. **更新状态**：task 实施记录、计划、文档影响  
6. **汇报事实**：完成/受阻/验证结果/下一步  

## 任务文件最低字段

每个 `docs/tasks/task-XXX.md` 应含：

- 状态、目标、背景
- 允许修改 / 禁止修改
- 验证命令与完成标准
- 实施记录、修改文件、验证结果、文档影响、风险、下一步

## 并行规则

- 可并行只读分析
- 同一工作区默认一个写者
- 需要并行写时用独立 worktree/分支并划清文件边界

## 完成检查清单

- [ ] 已读入口规则与当前 task  
- [ ] 只处理一个 task  
- [ ] 改动在允许范围内  
- [ ] 已真实验证或记录 blocker  
- [ ] 已更新 task 与必要文档  
- [ ] 未泄露本机路径/密钥到共享 docs
